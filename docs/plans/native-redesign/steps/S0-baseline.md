## เป้าหมาย
มีตัวเลขอ้างอิงของ 14 หน้าที่วัดซ้ำได้ และชุดตรวจที่อยู่ถาวรในโปรเจกต์ เพื่อให้ทุกขั้นถัดไปพิสูจน์ได้ว่าไม่ทำของเดิมพัง

## ผลลัพธ์ที่ตรวจได้
1. ไฟล์บันทึกตัวเลขอ้างอิงครบ 14 หน้าที่ 390 และ 1440 พิกเซล
2. ชุดตรวจอยู่ในโปรเจกต์ รันซ้ำได้ด้วยคำสั่งเดียว และไม่พึ่งไฟล์ใน /tmp
3. เซิร์ฟเวอร์ทดสอบส่ง CSP เดียวกับเว็บจริง
4. รัน 2 ครั้งติดกันได้ผลเท่ากัน

## ข้อเท็จจริงที่ตรวจแล้ว (วัด 17 ต.ค. 2026)
- มี 14 หน้า ได้แก่ community 3, data/verse 2, home, index, platform 5, search, setting
- ไฟล์ CSS 21 ไฟล์ รวม 162,220 ไบต์ [วัด: count assets/css/*.css => 21]
- กฎ hover active focus 138 บรรทัด ต้องไม่ลดลงในทุกขั้น
- สีฐานสิบหกที่ฝังในไฟล์ CSS นอก tokens.css มี 354 จุด
- radius แบบกำหนดเป็นพิกเซลโดยตรงเหลือ 4 บรรทัด
- แต่ละหน้าโหลดชุด CSS ต่างกัน หน้า data/verse/discover โหลดชุด nav-core ซึ่งต่างจากหน้าอื่น
- แถบเมนูจริงคือคลาส bottom-nav ไม่ใช่แท็ก nav
- เซิร์ฟเวอร์ทดสอบในเครื่องที่ไม่ส่ง CSP ทำให้ผลวัดต่างจากเว็บจริง (เจอแล้วในรอบสีเขียว)
- ชุดตรวจเดิมอยู่ใน /tmp และ .agents/.state/work/color-hierarchy-restraint/ ยังไม่อยู่ในโปรเจกต์

## สิ่งที่ยังไม่ทราบ
- หน้า index.html ที่ราก ทำหน้าที่เป็นหน้าอะไรจริงหรือเป็นแค่ตัวเปลี่ยนเส้นทาง
- หน้า data/verse/scope และ discover มีฟังก์ชันอะไรบ้างที่ต้องมีตัวตรวจเฉพาะ
- ตัวเลขอ้างอิงภาพ (screenshot) ควรเก็บเป็นไฟล์ภาพหรือเป็นตัวเลขวัดเท่านั้น

## แผนลงมือ
ขั้นย่อยเรียงตามลำดับ:
1. สำรวจ 14 หน้า จดฟังก์ชันที่ต้องตรวจของแต่ละหน้า
2. ย้ายชุดตรวจที่ใช้ได้เข้าโปรเจกต์ และทำให้เซิร์ฟเวอร์ทดสอบส่ง CSP จาก dist/_headers
3. เพิ่มตัวตรวจ: เลื่อนแนวนอน, radius จริง, สัดส่วนสี, contrast, ขนาดพื้นที่แตะ, ตำแหน่งแถบเมนู
4. วัดครบ 14 หน้าสองขนาดจอ บันทึกเป็นไฟล์ตัวเลขอ้างอิง
5. รันซ้ำเพื่อยืนยันว่าผลคงที่

ย้อนกลับ: ขั้นนี้ไม่แก้โค้ดของเว็บ เพิ่มเฉพาะไฟล์ตรวจ ย้อนด้วยการลบโฟลเดอร์ตรวจ

ความเสี่ยงที่ต้องคุม:
- ผลวัดที่ต่างจากเว็บจริงเพราะ CSP ต้องตรวจก่อนเชื่อทุกตัวเลข
- แถบเมนูเป็นคลาส bottom-nav การเลือกด้วยแท็ก nav จะได้องค์ประกอบผิด
- สแกนระหว่างอนิเมชันป๊อปอัปกำลังเข้า ทำให้ contrast ผิด ต้องปิดป๊อปอัปหรือรอให้นิ่งก่อนวัด

## การตัดสินใจที่ตรวจแล้ว (ไม่ต้องรอ Master)
เก็บตัวเลขอ้างอิงเป็นตัวเลขวัดเป็นหลัก เพราะภาพหน้าจอเปรียบเทียบพิกเซลเปราะบางต่อฟอนต์และเวลาโหลด
