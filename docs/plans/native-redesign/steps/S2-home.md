# S2 หน้าหลักและการเลือกหมวด

- **System Described**: หน้า Home ของ FanHoard เป็นโครงแอปที่สลับหมวดด้วยแถบแคปซูล
- **Entry File**: `docs/plans/native-redesign/steps/S2-home.md`
- **Dependencies**: `home/index.html`, `assets/js/home.js`, `assets/css/home.css`, `assets/db/con-data/index.json`
- **Verification**: `npm run build` | ชุดตรวจใน `scripts/design-checks/`

กลับไปที่ [แผนหลัก](../MASTER-PLAN.md) | ขั้นก่อนหน้า [S1](S1-component-system.md) | ขั้นถัดไป [S3](S3-search-discover.md)

ช่วง: กลาง (รายละเอียดบางส่วน)

## เป้าหมาย
Home เป็นโครงแอป: แถบแคปซูลสลับหมวดด้านบน แสดงทีละหมวด แทนลิสต์ยาวต่อเนื่อง ใช้องค์ประกอบกลางจาก S1

## ผลลัพธ์ที่ตรวจได้
1. สลับหมวดด้วยแตะแถบแคปซูล เห็นเฉพาะหมวดที่เลือก
2. แตะการ์ดแล้วคัดลอกได้เหมือนเดิม และมีการแจ้งเตือนว่าคัดลอกแล้ว
3. ปุ่มเลื่อนซ้ายขวาของแถวการ์ดเดิมยังทำงาน หรือมีสิ่งทดแทนที่ใช้ได้เท่ากัน
4. ผ่านตัวตรวจเลื่อนแนวนอน contrast พื้นที่แตะ และไม่มี error ของหน้า
5. ป๊อปอัปแจ้งอัปเดตปิดด้วย Escape แล้ว scroll-lock ปลด
6. การสลับหมวดเป็นแบบอินไลน์บนหน้า ไม่เปิดโมดัลหรือแผ่นล่าง (แผ่นล่างใช้เฉพาะงานที่ต้องโฟกัส เช่น เลือกตัวเลือกรายการ)

## ข้อเท็จจริงที่ตรวจแล้ว
- การ์ดทั้งหมดถูก JS วาดจากไฟล์ข้อมูล home.js 487 บรรทัด HTML ไม่มีเนื้อหาการ์ด
- วัด 17 ต.ค. 2026 (baseline.md): ที่จอ 390 สูง 5,255 พิกเซล ที่จอ 1440 สูง 5,077 พิกเซล มีการ์ดอีโมจิ 252 ใบ (ตัวเลข 258 ที่เคยอ้างผิด)
- ข้อมูลมาจาก assets/db/con-data/index.json แล้วโหลดไฟล์ของแต่ละหมวด
- มี noscript และ h1 หนึ่งตัวใน HTML

## สิ่งที่ยังไม่ทราบ
- หมวดใดควรเป็นหมวดเริ่มต้นเมื่อเปิดหน้า
- ควรจำหมวดที่เลือกล่าสุดข้ามการเปิดหน้าหรือไม่
- จำนวนหมวดที่แสดงบนแถบแคปซูลได้โดยไม่แน่นเกินไป (ชนิด 4 กลุ่ม หมวดรวมกว่า 35)
- ต้องแยกแคปซูลเป็นสองชั้น (ชนิด แล้วหมวด) หรือไม่
