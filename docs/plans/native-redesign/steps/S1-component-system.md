# S1 ระบบองค์ประกอบกลาง

- **System Described**: ชุดองค์ประกอบแบบแอปที่ใช้ร่วมกันทุกหน้าของ FanHoard
- **Entry File**: `docs/plans/native-redesign/steps/S1-component-system.md`
- **Dependencies**: `assets/css/tokens.css`, `assets/css/base.css`, `assets/css/layout.css`, `docs/plans/native-redesign/steps/S0-baseline.md`
- **Verification**: `npm run build` | ชุดตรวจใน `scripts/design-checks/`

กลับไปที่ [แผนหลัก](../MASTER-PLAN.md) | ขั้นก่อนหน้า [S0](S0-baseline.md) | ขั้นถัดไป [S2](S2-home.md)

ช่วง: ใกล้ (รายละเอียดเต็ม)

## เป้าหมาย
มีชุดองค์ประกอบกลางที่เป็น "ภาษาเดียว" ของทั้งเว็บ ให้ขั้นถัดไปเลือกใช้ ไม่ต้องเขียนหน้าตาใหม่ทีละหน้า

## ผลลัพธ์ที่ตรวจได้
1. องค์ประกอบครบชุด: แถบหัวหน้า, การ์ด, แถวรายการในการ์ด, ปุ่มแคปซูล, แถบแคปซูลสลับหมวด, แผ่นล่าง, สถานะว่าง, ช่องค้นหา
2. ทุกองค์ประกอบใช้ค่าจากโทเค็นเท่านั้น ไม่มีสีฐานสิบหกฝังในองค์ประกอบใหม่
3. ระบบตัวอักษรหนึ่งชุด (ขนาด น้ำหนัก ระยะบรรทัด) ใช้ system-ui ไม่เพิ่มไฟล์ฟอนต์
4. มีหน้าตัวอย่างหนึ่งหน้าที่ใช้ครบทุกองค์ประกอบ และผ่านตัวตรวจเลื่อนแนวนอน contrast และพื้นที่แตะ
5. กฎ hover active focus ไม่ลดจาก 138 บรรทัด
6. องค์ประกอบซ้อนกันไม่เกิน 3 ชั้น ไม่มีการ์ดซ้อนการ์ด (การ์ดที่อยู่ในการ์ดใช้ระยะหรือสีจางแยก ไม่ใช้พื้นหรือขอบซ้ำ)
7. การ์ดไอเทมอีโมจิ (ตารางข้อมูล ขนาดเท่ากันโดยธรรมชาติ) แยกจากโครงหน้า โครงหน้าไม่ใช้การ์ดไอคอนกับหัวข้อกับข้อความขนาดเท่ากันซ้ำ ๆ
8. ทุกองค์ประกอบที่ซ้อนกันมีรัศมีด้านในเท่ากับรัศมีด้านนอกลบระยะขอบใน (รัศมีซ้อนแบบรวมศูนย์)

## ข้อเท็จจริงที่ตรวจแล้ว
- โทเค็นรัศมีมีอยู่แล้ว: การ์ด 28 แผง 32 ปุ่มแคปซูล (จากรอบก่อน)
- พื้นผิวเป็นขาวและขอบเทา สีเขียวใช้เฉพาะปุ่ม ลิงก์ รายการที่เลือก และกรอบโฟกัส (v5.7.x)
- ป๊อปอัปใช้ var(--fp-bg, var(--surface-card)) และธีมมืดอ่านออกแล้ว (v5.7.1)
- ภาพตัวอย่างของ Master ใช้ร่วมกัน: พื้นขาวหรือเทาอ่อน การ์ดโค้งใหญ่ ขอบบาง ไอคอนเส้นหนาในวงกลมเทา ปุ่มแคปซูล แท็บล่างไอคอนล้วน แผ่นล่าง และรายการแถวคั่นเส้นบาง
- เว็บเป็นภาษาสองภาษา (ไทยและอังกฤษ) ข้อความองค์ประกอบต้องรองรับความยาวต่างกัน
- สกิล design-system-governance แนะนำสัดส่วนสี 60/30/10 และเตือนว่าถ้าสีเน้นต่ำกว่าราว 5% หน้าอาจดูแบน โปรเจกต์วัดได้ 0.8 ถึง 3.3% (Master สั่งลดเขียวใน v5.7.0) จึงต่ำกว่าเกณฑ์ของสกิลโดยตั้งใจ
- สเกลรัศมีของสกิลต่างจากที่โปรเจกต์ใช้ (สกิล 28/40/52 โปรเจกต์ 28/32/แคปซูล) ใช้ค่าที่ Master อนุมัติแล้วเป็นหลัก ไม่ปรับตามสกิล

## สิ่งที่ยังไม่ทราบ
- ภาพ Instagram และ Threads ที่ Master จะส่ง อาจเพิ่มหรือเปลี่ยนองค์ประกอบ
- ตัวหนาของภาษาไทยใน system-ui แสดงต่างกันตามเครื่อง ต้องวัดบน Android จริง
- แถบเมนูล่างปัจจุบันมี 4 ปุ่ม ต้องตัดสินว่าต้องเปลี่ยนหรือไม่ (ตอนนี้ล็อกให้คงตำแหน่งและพฤติกรรม)

## แผนลงมือ
ขั้นย่อยเรียงตามลำดับ:
1. ตรวจสอบโทเค็นเดิม ระบุที่ขาดสำหรับองค์ประกอบใหม่
2. กำหนดระบบตัวอักษรและระยะเป็นโทเค็น
3. สร้างองค์ประกอบทีละตัว เรียงจากเล็กไปใหญ่ (ปุ่ม, แคปซูล, การ์ด, แถวรายการ, แถบหัว, แผ่นล่าง, สถานะว่าง)
4. สร้างหน้าตัวอย่างภายในเพื่อดูทั้งชุดรวมกัน (ไม่ลิงก์จากเมนู ไม่ขึ้นเว็บจริง)
5. ตรวจเกณฑ์ผลลัพธ์ 1 ถึง 5 ผ่านชุดตรวจ แล้วเทียบกับตัวเลขอ้างอิงจาก S0

ย้อนกลับ: องค์ประกอบใหม่เป็นไฟล์ใหม่ ยังไม่ผูกกับหน้าใด ย้อนด้วยการลบไฟล์ใหม่ ไม่กระทบหน้าที่ใช้อยู่

ความเสี่ยงที่ต้องคุม:
- ชื่อคลาสใหม่ชนกับคลาสเดิม ต้องใช้คำนำหน้าเฉพาะ
- ความจำเพาะ (specificity) ของตัวเลือก CSS ใหม่ทับของเดิมจนหน้าอื่นเพี้ยน
- ทำสวยเกินจนละเลยภาษาไทยที่ยาวกว่า
- ลดเขียวแล้วหน้าดูแบน ตัวตนต้องมาจากอีโมจิ ระยะ และตัวอักษร ไม่ใช่สีเน้น ต้องตรวจด้วยตาจริงบนหน้าตัวอย่างก่อนไปขั้นถัดไป

## การตัดสินใจที่ตรวจแล้ว (ไม่ต้องรอ Master)
ขั้นนี้ไม่ปล่อยขึ้นเว็บจริง เพราะยังไม่มีหน้าไหนใช้ จึงไม่ต้องมีรุ่นใหม่ ปล่อยพร้อม S2 เมื่อมีหน้าแรกที่ใช้
