**TL;DR** — แก้ไข 2 จุดตามรายงานจากการทดสอบบนเบราว์เซอร์จริง: (1) หน้าค้นหาเคยมองเห็นการ์ดได้แค่ใบบนสุด เพราะ transition ตอนปรากฏตัวเคลื่อน `transform` ของ wrapper ของ URE จนเขียนทับการวางตำแหน่งของ virtual scroll ทำให้การ์ดทุกใบซ้อนกันที่จุดเดียม — ตอนนี้ wrapper ใช้เฉพาะ fade opacity ทุกผลลัพธ์เรนเดอร์ตามตำแหน่งของตัวเองแล้ว (2) คืนอนิเมชั่น `.active` แบบพรีเมี่ยมดั้งเดิมบนปุ่มนำทางหลัก (เส้นใต้แบบ spring overshoot) และปุ่มหมวดหมู่ไม่หดตัวถาวรขณะถูกเลือกอีกต่อไป พร้อมเพิ่ม E2E guard กันบั๊กซ้อนกันกลับมา

### แก้ไข

- **การเรนเดอร์ผลลัพธ์ค้นหา (`assets/js/ure/ure.css`)**
  URE virtual scroll วางตำแหน่ง wrapper ของทุกการ์ดด้วย inline `transform` (ดู `virtual-list.js`) แต่ transition ปรากฏตัวที่เพิ่มใน v3.2.8 ไปเคลื่อน `transform` ของ wrapper `.ure-visible` ด้วย ซึ่ง CSS animation จะ override inline style ทำให้การ์ดทุกใบในหน้าต่างแรกไปอยู่ที่ `translateY(0)` ซ้อนกันหมด เหลือเห็นเฉพาะใบบนสุด ตอนนี้ wrapper ของ URE ใช้ fade เฉพาะ opacity (`ure-appear-fade`) ไม่แตะตำแหน่งของ engine แล้ว ส่วนกลุ่มเนื้อหา `.cm-group` / `.feed-page` ยังคง appear เนียนเหมือนเดิม
- **คืนอนิเมชั่นปุ่ม Active ต้นฉบับ (`assets/css/nav-core.css`, `nav-core-ext.css`)**
  คืนอนิเมชั่น active indicator ดั้งเดิมบนปุ่มนำทางหลัก: เส้นใต้เลื่อนเข้าด้วย `200ms ease-in` แล้วเด้งออกด้วย overshoot curve ที่ออกแบบไว้ `400ms cubic-bezier(0.34, 1.56, 0.64, 1)` และปุ่มหมวดหมู่ (`.button-sub`) ไม่เหลืออาการหดตัวถาวร `scale(0.97)` ขณะอยู่ในสถานะ `.active` แล้ว — การหดเหลือเฉพาะตอนกด (`:active`) จริง ๆ เท่านั้น

### ผ่านการตรวจสอบ

- **เพิ่ม E2E regression guard** — `e2e/search-refresh-regression.spec.ts` ตรวจว่าการ์ดผลลัพธ์เรนเดอร์คนละตำแหน่งกัน (ไม่มีการซ้อนจาก transform override) เทสนี้ fail บนสถานะพังและผ่านหลังแก้
- Unit 234/234 ผ่าน (37 ไฟล์) และ E2E เต็มชุด 16/16 ผ่าน รวม scroll-lock 3/3
- ตรวจ effective DOM state ในเบราว์เซอร์จริง: การ์ดหน้าต่างแรกทั้ง 12 ใบอยู่คนละตำแหน่งและมองเห็นครบ กลุ่ม feed ในหน้า discover เรนเดอร์ตาม flow ปกติถูกต้อง
