**TL;DR** — Loading screens, popups, and search overlays now use a single unified scroll-lock authority. Stacked overlays (such as a modal popup over a fullscreen loading state) compose safely without unlocking the background page when one closes, while reading scroll position and scrollbar layout are always cleanly preserved.

### Key Improvements

- **Unified Overlay Scroll-Lock Authority**
  Loading screens, modal popups, and search overlays now route scroll-locking through a central reference-counted core (`ScrollLockCore`). Opening multiple stacked overlays maintains background scroll locks until every active overlay has closed, eliminating early background scroll unlock bugs.
- **Universal Availability & Soft Fallback**
  The scroll-lock core operates consistently across all site pages, including lightweight pages without full Fast-Visual-Loading (FVL) assets. Soft fallbacks ensure overlays remain fully functional in any environment.
- **Scroll Position & Layout Compensation**
  Background scroll position is pinned precisely without layout shifting, with layout scrollbar compensation and full respect for reduced-motion accessibility preferences.
- **Observable State & Hard Reset Safety**
  Exposes observable `data-scroll-locked` DOM attribute state for accessibility and automated testing, with built-in hard reset restoration that cleans up body and html styles under all teardown conditions.

### Reliability & Testing

- Added 8 unit contract tests in `tests/scroll-lock-core.test.ts` verifying reference counts, owner tags, and DOM reset behavior.
- Added 3 Playwright browser e2e tests in `e2e/scroll-lock.spec.ts` covering fullscreen loading, stacked overlay composition, and search overlay lock/unlock cycles.
